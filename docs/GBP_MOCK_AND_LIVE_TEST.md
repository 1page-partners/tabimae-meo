# GBP連携のモック検証と実接続検証

Google Business Profile APIには公式サンドボックスがありません。このリポジトリのモックは**アプリ側の開発用応答**であり、Googleの認証やAPI権限を確認したことにはなりません。

## 本番でモックを試す

`https://tabimae-meo.netlify.app/gbp-test` で模擬接続・施設選択・口コミ同期・解除を試せます。このページは専用のモックAPIだけを呼び出し、本番のGoogle APIやSupabaseにはアクセスしません。接続状態はブラウザーのlocalStorageだけに保存します。通常の `/settings` は実接続のままです。

## ローカルでモックを試す

1. `npm run dev` を起動します。専用の `/gbp-test` は環境変数の指定なしで利用できます。通常画面も模擬する場合だけ `.env.local` に `VITE_GBP_MOCK=true` を指定して再起動します。このフラグは開発ビルドでのみ有効です。
2. /gbp-test を開きます。この独立した開発用ページはGoogle・Supabaseの資格情報なしで、模擬接続→施設選択→口コミ同期→解除を操作できます。
3. 既存の /settings と /reviews でも確認する場合は、Supabaseの開発環境に施設ユーザーでログインします。GBP応答と例示口コミは模擬され、施設情報などGBP以外の画面は従来どおりSupabaseを使います。
4. 模擬の接続状態と返信は施設IDごとにブラウザーのlocalStorageへ保存されます。投稿の公開は模擬モードで拒否します。
5. node --test tests/gbp-oauth.test.mjs tests/gbp-mock.test.mjs でローカルの応答契約を確認します。

模擬の施設名、口コミ、同期件数、MEOスコアは実データではありません。GoogleのOAuth、権限、API応答、実際の口コミ投稿はこのモードでは未検証です。実データとの混同を避けるため、通常画面をモックへ切り替える開発フラグは本番で無効です。本番でのモック検証は専用の `/gbp-test` を使ってください。

## 実接続に切り替える

1. VITE_GBP_MOCK を削除または false にして開発サーバーを再起動します。モックのlocalStorageは実接続の状態に使われません。
2. [公式のGBP API前提条件](https://developers.google.com/my-business/content/prereqs)に従い、確認済みの実在するビジネスプロフィール、ウェブサイト、APIアクセス承認を用意します。対象プロフィールの管理者権限を持つGoogleアカウントで試します。
3. docs/GBP_OAUTH_SETUP.md に沿ってGoogle CloudとSupabase Secretsを設定し、Edge Functionsをデプロイします。シークレットを VITE_ 変数に入れないでください。
4. 読み取りから確認します。ログイン→接続→施設一覧と選択→状態表示→口コミ同期→DB上の口コミ件数を照合します。施設が複数なら誤接続しないこと、権限不足・API未承認時のエラー、解除後の状態も確認します。
5. 返信・投稿など外部に見える書き込みは、管理権限と検証対象を確認した上で別途実施します。

**実接続の合格条件**: Googleの同意画面から戻り、実施設名が表示され、口コミの実件数と内容が一致し、再読み込み後も接続状態が維持されること。モックテストの成功だけで実接続済みとは扱いません。
